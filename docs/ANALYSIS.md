# Анализ возможностей Codex Companion

Дата исходного анализа: 16 октября 2026 года. Ниже сохранена предварительная оценка. Актуальная реализация через стандартное окно Codex описана в [IMPLEMENTATION.md](IMPLEMENTATION.md); прежний выбор собственного чата отменён пользователем.

## Выводы из анализа исходного companion проекта

Полезные сценарии: восстановление рабочих панелей, названия диалогов, возврат закрытого окна, квоты в статус-баре, подробный отчёт, уведомления и диагностика. Переносим идеи интерфейса; зависимости от прежнего провайдера не нужны.

Уроки для новой архитектуры:

- Управление чужими webview через текстовые врезки в установленное расширение привязано к его версии.
- Идентификатор панели должен быть стабильным: название вместе с ID сессии не подходит, поскольку переименование может ошибочно выглядеть как закрытие.
- Прогноз расхода по среднему темпу с начала окна приблизителен. Для прогноза по недавней активности нужна история измерений.
- UI, интеграцию с агентом, хранение состояния и расчёт квот стоит разделить на модули.
- Документация должна соответствовать текущему поведению меню и уведомлений.

## Локальное окружение на момент анализа

- Windows, PowerShell, VS Code.
- Расширение `openai.chatgpt`: `26.1007.21434`.
- Доступный CLI: `codex-cli 0.162.0-alpha.17.2`.
- В CLI доступна команда `codex app-server`; справка помечает её как experimental.

В manifest установленного расширения найдены команды:

- `chatgpt.openSidebar` — открытие сайдбара.
- `chatgpt.newCodexPanel` — новая панель агента.
- `chatgpt.openCommandMenu` — меню Codex.
- `chatgpt.addToThread` — добавление выделенного контекста.
- `chatgpt.addFileToThread` — добавление файла.
- `chatgpt.newChat` — новый диалог в сайдбаре.

Наличие команд проверено чтением manifest; вызовы команд из отдельного расширения не тестировались. В изученном списке нет публичной команды переименования конкретной вкладки или загрузки заданной сессии в неё.

## Документированный протокол

[Codex App Server](https://learn.chatgpt.com/docs/app-server) описывает:

- `account/rateLimits/read` и `account/rateLimits/updated` — получение квот и события обновления.
- `thread/list`, `thread/read` — сохранённые диалоги и метаданные.
- `thread/name/set` — имя диалога.
- `thread/resume`, `thread/fork` — продолжение и ответвление истории.
- `thread/tokenUsage/updated` — расход токенов активного диалога.

Продолжительность окон, процент использования и время сброса квот нужно брать из ответа сервера. Нельзя жёстко переносить месячный лимит или фиксированный набор окон другого продукта. Некоторые поля и методы зависят от версии и experimental-возможностей.

Документированные команды IDE: [Developer commands](https://learn.chatgpt.com/docs/developer-commands?surface=ide).

## Границы интеграции

Доступ к истории через App Server не даёт автоматически доступ к панелям официального расширения. Переименование диалога и переименование заголовка вкладки — разные операции.

Отдельный процесс App Server нельзя заранее считать источником событий всех задач, выполняющихся в официальном расширении. Требуется проверить совместное хранилище, модель подключения и область событий. Не запускать одновременное продолжение одного диалога из разных клиентов без проверки поведения.

Получение квот на аккаунте пользователя пока не проверялось. Проверки авторизации, аккаунта, доступных методов и событий относятся к будущей интеграционной работе после разрешения начать реализацию. Секреты и содержимое диалогов в эти документы не переносились.

## Оценка функций

| Функция | Предварительная оценка |
| --- | --- |
| Статус-бар, команды, меню, диагностика | Реализуемы в companion-расширении |
| Квоты и предупреждения | Нужна проверка App Server с текущей авторизацией |
| Каталог и поиск сессий | Есть протокольная основа; проверить доступность истории |
| Переименование диалога | Документировано; синхронизация UI требует проверки |
| Продолжение и ответвление | Документированы для клиента App Server |
| Восстановление собственных панелей | Контролируется новым расширением |
| Восстановление официальных вкладок | Надёжный способ пока не установлен |
| Уведомления о ходе задач | Для задач, события которых доступны клиенту |

Предпочтительный подход: официальные команды и протокол. Собственный чат рассматривать отдельно, если подтверждённые сценарии требуют полного контроля панелей.
