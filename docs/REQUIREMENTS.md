## Сохраняемое поведение

История recent/full/search локального Codex по проекту; мгновенное штатное имя;
проектная пара модель/effort из штатного UI; [~]/[V]/[!]/[?], однократный звук
на новое успешное [V], silent restore. Облачная история и session picker VS Code
не фильтруются. Sandbox/auth/history/права доступа/черновики не переносить и не
удалять. Рабочие окна/задачи не закрывать, не reload и не возобновлять автоматически.

В 26.1021.22027 карточки асинхронных вопросов (`agentMessage.questions`) включают `[?]`.
Неразрешённый запрос ответа сохраняет ожидание при последующих событиях работы;
асинхронная карточка сохраняет его и после успешного завершения turn, без `[V]`
и звука. Обычный текст без структурированных вопросов не распознавать по знакам
препинания. Ошибка или прерывание должны сохранять свой терминальный статус.
Слой 26.1007.21434 сохранён побайтно; это исправление в него не переносилось.

Переход idle → waiting на нативных async-карточках уведомляет «нужен ваш ответ»
(`needs your answer` в английском UI) и играет отдельный короткий синтезированный
`waiting.wav` 0.32 с; прежний звук завершения не меняется. Настройки уведомлений,
окон и звука сохраняются, mute глушит оба сигнала. Счётчик `[? N]` ведёт
WorkflowUi по `onStatusEvent`, независимо от дедупликации уведомлений.
Дедупликация — логический `eventId`: отдельное уведомление на каждый вопрос
внутри одного turn не гарантируется; replay/snapshot молчат.

## Восстановление статусов — 0.2.7

После reload Companion восстанавливает статусы вкладок 26.1021.22027 только по
уже существующим запросам/ответам `thread/read` самой панели. Собственного RPC
или второго App Server, опроса, наблюдения за другими клиентами, сообщений
модели, автоматического reload, возобновления задач и публикации нет.

- Снимок `live:false` обновляет название и счётчик внимания, но не создаёт
  уведомлений и звуков; последующие live-события работают обычно.
- `includeTurns:false` восстанавливает только runtime active flags и
  `systemError`; idle/notLoaded без turns статус не выдумывают.
- Полный `turns`: inProgress → running/waiting, completed → done, failed → error,
  interrupted/cancelled/canceled → idle. Незавершённая цель сохраняется
  (active → running, иначе waiting) и не даёт ложного `[V]`.
- Вопросы сопоставляются только по точному native-конверту ответа и
  `questionItemId`; частичный ответ закрывает только указанные вопросы,
  отклонённое steering чужие вопросы не закрывает.
- Неразрешённые вопросы completed turn удерживают idle или прежнее waiting и не
  считаются надёжным восстановлением. При missing/paginated данных точное
  состояние вопросов неизвестно.
- Записи чтения ограничены 64; проверяются thread/turn, `requestSeq` и live epoch;
  запись очищается по ответу, ошибке, abandon, неудачной доставке и dispose
  webview.
- Слой 26.1007 runtime/metadata побайтно прежний; на 26.1021 меняются только host
  workflow/drafts, остальные webview/pre-workflow стадии прежние.

Вопросы завершённого хода при полной истории поддержаны в 0.2.9; неполные данные
сохраняют известное состояние. Изображения и история квот остаются backlog.
