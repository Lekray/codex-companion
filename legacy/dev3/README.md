# Codex Companion

Локальное расширение VS Code для Codex: отдельные вкладки, независимые названия, статусы задач, восстановление диалогов, квоты и уведомления.

Первая реализация `0.1.0-dev.3`. Собственные вкладки и Codex App Server выбраны пользователем после проверки ограничений официального расширения. Проверено на локальном Windows, VS Code 1.139.1, Codex 26.1007.21434 и CLI 0.162.0-alpha.17.2.

## Использование

Откройте папку проекта и выполните `Codex: Открыть` в палитре команд. Каждое нажатие создаёт вкладку `Codex 1`, `Codex 2` и далее. Кнопки открытия, переименования и истории находятся над редактором. Переименование меняет только вкладку Companion.

Введите задачу и нажмите «Отправить» или Ctrl+Enter. Ответ поступает потоком; результаты инструментов сворачиваются. «Остановить» прерывает задачу. Запросы разрешений и вопросы отображаются в ленте и требуют явного ответа.

Статусы: `[~]` работает, `[V]` выполнено, `[!]` ошибка, `[?]` ждёт ответа. У новой вкладки отметки нет. При закрытии работающей вкладки предлагаются фон, остановка или отмена. VS Code уже закрывает webview к этому моменту, поэтому отмена восстанавливает вкладку.

После перезапуска сохраняются вкладки, названия и диалоги. Выполнение возобновляется только после отправки сообщения. Пустая вкладка сохраняется локально; серверный диалог создаётся при первой отправке. Закрытые диалоги доступны через `Codex: История` этого проекта.

Строка состояния показывает возвращённые сервером группы квот: использованный процент и время до сброса. Нажатие обновляет данные; автоматическое обновление — раз в минуту. При ошибке данные отмечаются как устаревшие. Проценты не являются подтверждением доступности модели.

В активном окне используются уведомления VS Code, в фоне — Windows, с названием проекта и вкладки. Нажатие вызывает переход в исходное окно и вкладку. Windows может скрывать уведомления своими системными настройками.

## Разработка и сборка

Нужны Node.js 22.22.2+ или поддерживаемая новая LTS и установленный Codex CLI с действующим входом в ChatGPT. По умолчанию берётся CLI официального расширения, затем из PATH. Companion не выполняет вход и не копирует токены.

```powershell
npm ci
npm test
npm run probe
npm run package
```

F5 запускает отдельное окно разработки. Установочный файл создаётся в `.artifacts/codex-companion-0.1.0-dev.3.vsix`. Сборка не устанавливает и не публикует расширение.

Дополнительные проверки:

```powershell
$env:CODEX_COMPANION_CLI = (Get-Command codex).Source
npm run test:host
npm run test:ui
npm run test:live
npm run test:notification
npm run test:workbench
npm run test:history
```

`test:host` использует отдельные профили VS Code и Codex и проверяет полный перезапуск. `test:ui` запускает установленный Edge без окна; путь задаётся через `COMPANION_TEST_BROWSER`. `test:live` выполняет один временный запрос к настоящему Codex в режиме чтения и расходует небольшую часть квоты. `test:notification` показывает тестовое уведомление Windows.

`test:workbench` проверяет в настоящем VS Code закрытие работающей вкладки, отмену, фон, остановку и ответы на запросы; сервер в этом тесте синтетический, обращения к модели нет. `test:history` создаёт реальный тестовый диалог в режиме чтения, проверяет историю после смены процесса App Server и архивирует только созданный тестом диалог.

Интерактивный прогон `npm run test:notification-focus` открывает два тестовых окна и ждёт ручного клика по собственному toast. После клика автоматически проверяются исходное окно и вкладка. Такой прогон пройден. `npm run test:toast-click` отдельно проверяет сигнал клика. Нажать нужно во время показа баннера; автоматический доступ UI Automation к нему Windows в этой среде запрещает.

## Настройки

| Настройка | По умолчанию |
| --- | --- |
| `codexCompanion.cliPath` | Автоматический поиск CLI |
| `codexCompanion.windowsNotifications` | Включены |
| `codexCompanion.notificationSound` | Выключен |

Язык команд и интерфейса выбирается по языку VS Code: русский или английский. Модель и правила выполнения берутся из настроек Codex. Companion не ослабляет разрешения автоматически. Неизвестные клиентские запросы отклоняются.

## Границы текущей версии

- Companion управляет своими диалогами. Задачи официального интерфейса Codex и других клиентов не включаются в его статусы и уведомления.
- Задачи в фоне продолжаются при закрытии вкладки, пока работает соответствующее окно VS Code. Закрытие самого окна завершает принадлежащий ему App Server.
- История меню содержит диалоги, созданные Companion в текущем рабочем пространстве.
- Интерфейс текстовый: без вложений, встроенных приложений MCP и редактирования файлов прямо в ленте. Неподдерживаемые клиентские запросы дополнительных возможностей возвращают ошибку, не разрешение.
- После аварийного разрыва соединения следующая команда или обновление квот создаёт новое подключение; задачи сами не перезапускаются.
- Проверен переход из свежего Windows-баннера. Переход из старой записи центра уведомлений после окончания показа пока не гарантируется: нативный процесс уже завершил ожидание.
- App Server экспериментальный; обновление Codex требует повторной проверки совместимости.
